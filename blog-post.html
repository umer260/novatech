How we cut a support queue by 40% with a retrieval chatbot

Usman TariqOct 14, 20267 min read

Start with the tickets, not the model

Before writing code we labelled 800 past tickets. Sixty percent were repeat questions with answers already in the help centre. That number told us a retrieval chatbot was worth building.

Retrieval beats fine-tuning here

Instead of training a model on support history, we index the help documents and let the model answer only from what it retrieves. When retrieval finds nothing relevant, the bot hands the chat to a person.

Rule of thumb: if the bot cannot cite a document, it should not answer.

Three metrics that mattered

  • Deflection rate: chats resolved with no agent.
  • Wrong-answer rate, sampled weekly by humans.
  • Time to first useful reply.

What we would do differently

We under-invested in document hygiene. Outdated help pages produced outdated answers, so we now schedule a content review before every launch.
